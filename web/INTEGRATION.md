# 웹 ↔ Mac 에이전트 연결

## 현재 구현

1. Mac의 `file-lifecycle-agent/prototype/demo_v5.py`는 `127.0.0.1`의 로컬 API를 제공합니다.
2. `web/bridge/mac_bridge.py`가 그 상태에서 파일명·판단 이유·계획·프로젝트 목록을 추려 HTTPS Django API로 전송합니다. 파일 내용과 전체 추론 trace는 전송하지 않습니다.
3. 로그인한 사용자는 운영 사이트 **에이전트 연결** 화면에서 상태를 보고 파일별 답변·승인·유지·되돌리기를 요청합니다.
4. Django는 사용자별 명령을 대기열에 저장합니다. Mac 브리지가 명령을 가져와 로컬 API에 전달하고 결과를 보고합니다.
5. 실행기는 승인 계획을 재계산하고 원본 해시·대상 충돌을 확인합니다. 결과 저널과 복구는 에이전트가 관리합니다.

브리지 토큰은 서버에 해시만 저장됩니다. 브리지는 서버로 연결을 시작하므로 Mac에 인바운드 포트를 열 필요가 없습니다. 브라우저 요청에는 Django 로그인 세션과 CSRF 검사가 적용됩니다. 한 브리지에는 한 번에 하나의 명령만 실행합니다.

## API

| 경로 | 용도 |
| --- | --- |
| `GET /api/v1/auth/session/`, `POST /api/v1/auth/login/`, `POST /api/v1/auth/logout/` | 웹 세션 |
| `GET /api/v1/agent/status/` | 로그인 사용자의 Mac 상태와 최근 명령 |
| `POST /api/v1/agent/commands/` | 답변·승인·유지·되돌리기·휴지통 복구 요청 |
| `POST /api/v1/agent/bridge/poll/`, `POST /api/v1/agent/bridge/result/` | Mac 브리지의 토큰 인증 상태 전송·명령 수신·결과 보고 |

기존 `/api/v1/files/`, `/folders/`, `/reviews/`는 데이터 계약 초안으로 남아 있고 실제 에이전트 상태의 원본은 아닙니다. 브라우저 예시 데이터와 시연 모드 전환은 제거했으며, 기존 예시 데이터 저장 키는 페이지를 열 때 정리합니다.

## 운영 전 남은 작업

- Mac에서 실제 에이전트와 브리지를 설치·실행하고 허용할 감시 폴더와 프로젝트를 지정해야 합니다.
- Mac 연결이 끊긴 채 실행 중이던 명령은 자동 재실행하지 않습니다. 에이전트 저널을 확인한 뒤 수동 복구해야 합니다.
- 사용자 비밀번호 변경·분실 복구, 로그인 시도 제한, 다중 사용자 운영 정책을 추가해야 합니다.
- 실제 모드의 설정과 폴더 지침 원격 수정은 추가 API가 필요합니다.


## 웹 실제 데이터 모드

웹은 연결한 Mac의 실제 데이터만 표시합니다. 연결 화면에서 로그인하면 대시보드·파일 검색·폴더·분류 대기·보관 대기·Mac 휴지통·명령 기록이 계정별 에이전트 상태를 사용합니다. 답변·이동 승인·유지·되돌리기·휴지통 복구는 기존 브리지 명령 API로 전달되며 5초마다 상태를 갱신합니다. 폴더 지침·감시 범위·모델 변경은 Mac에서 진행하고, 신규 파일 처리 방식과 보관 기한은 웹 설정에서 Mac별로 변경합니다. 브리지 업데이트 후 다시 실행해야 파일별 프로젝트 정보가 전송됩니다.

## 분류 전 파일 미리보기

파일 이름을 누르면 웹 미리보기 창을 엽니다. 연결된 Mac에 `preview` 명령을 보내 등록된 파일 ID만 읽으며, 분류·이동 상태는 변경하지 않습니다. 일괄 정리 제안 안의 파일도 지원합니다. 이 기능은 최신 Mac 연결 앱이 필요하고, 구버전이나 오프라인 상태에는 안내를 표시합니다.

사용자가 요청할 때만 텍스트 일부(최대 6,000자) 또는 JPEG 축소본(최대 28KB)을 기존 명령 결과 API로 전송합니다. 미리보기 결과는 해당 사용자 명령 기록에 저장됩니다. 원본은 업로드하지 않습니다. 20MB 초과 파일과 지원하지 않는 형식은 안내 후 중단합니다. PDF·DOCX·PPTX는 추출된 텍스트를 표시하므로 원본 레이아웃과 다를 수 있습니다.

## Mac별 정리 정책과 만료 예약

상태의 `snapshot.preferences`는 Mac에 실제 적용된 설정과 `revision`을 반환합니다. `preferences` 명령에 `settings`와 같은 revision을 보내며, 적용 결과와 다음 스냅샷을 확인한 뒤 저장 완료로 표시합니다. 신규 파일은 수신 시점의 모드와 현재 모드가 모두 자동일 때만 자동 정리하며, 기존 파일·새 폴더 생성은 확인받습니다.

`snapshot.expiry.entries`에 예약 ID·대상 파일명·종류·상태·Unix 초 단위 `due_at`을 표시합니다. `expiry_schedule(asset_id,due_at)`, `expiry_confirm(entry_id)`, `expiry_change(entry_id,due_at)`, `expiry_cancel(entry_id)` 명령을 사용합니다. 설치파일 기한은 기본 3일이고, 이름 단서로 제안하는 휘발성 자료는 기본 7일 승인 대기입니다. 제안은 의미·행사 날짜를 추론한 결과가 아니며 사용자가 기간을 확인합니다. 원본 경로·파일 해시·브리지 토큰은 이 계약에 포함하지 않습니다.

Mac이 분석 중이라 로컬 상태 조회가 지연되더라도 브리지는 마지막 스냅샷을 보존한 생존 신호를 보냅니다. 서버는 연결 상태를 유지하고 `agent_available=false`인 동안 새 작업 전달을 보류합니다. 기존 sslip.io 연결은 동일 서버의 https://3.38.192.19 로 연결 토큰을 보존해 이전하며, 다른 서버 주소는 바꾸지 않습니다.
