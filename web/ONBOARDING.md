# 회원가입 → Mac → iPhone 온보딩

진입 주소: `https://3.38.192.19/#signup` / 가이드 재개: `https://3.38.192.19/#onboarding`

0. **Dock에 추가**: Mac Safari에서 파일 → Dock에 추가 → 이름 모아 AWS → 추가를 안내합니다. Dock 아이콘으로 앱을 연 뒤 가입·로그인을 진행합니다. 앱 모드가 감지되거나 사용자가 이미 추가했다고 확인하면 이 안내를 건너뜁니다. 미지원 환경에서는 브라우저로 계속할 수 있습니다.
1. **모아 계정 만들기**: 아이디·선택 닉네임·비밀번호·확인 입력. 가입 후 자동 로그인하여 온보딩으로 이동합니다. Apple 개발자 가입은 필요 없습니다.
2. **Mac 연결**: AWS 화면의 **모아 연결 앱 다운로드**에서 ZIP을 받고 압축을 풀어 **Moa Helper** 앱을 한 번 엽니다. 앱이 Python과 연결 프로그램을 자동으로 설치합니다. AWS의 `설치한 앱으로 Mac 연결하기`에서 링크를 발급받고 연결 앱 창에서 승인합니다. 앱이 iCloud Drive의 KCC-inbox를 준비하고 AWS에 연결 상태를 전송합니다. 웹앱으로 돌아오면 다음 단계가 표시됩니다.
3. **iPhone 설정**: Mac의 웹 화면은 그대로 두고 iPhone의 설정·파일 앱만 사용합니다. iPhone에서 모아에 로그인할 필요는 없습니다. Mac과 같은 Apple 계정인지 확인하고 iCloud Drive의 `이 iPhone 동기화`를 켭니다. 파일 앱에서 `iCloud Drive/KCC-inbox`를 확인한 뒤 `KCC-inbox 폴더가 보여요`를 누릅니다. 이 항목은 사용자 확인이며 웹에서 Apple 계정을 조회하지 않습니다.
4. **전송 테스트**: 폴더 확인 후 QR로 iPhone 설치 안내를 엽니다. [공유 단축어](https://www.icloud.com/shortcuts/2e21efc91f794f02af4821c98ac64069)를 추가하고 파일 저장 동작에서 자신의 `iCloud Drive/KCC-inbox`를 지정합니다. 설정 → 손쉬운 사용 → 터치 → 뒷면 탭 → 이중 탭 → 단축어 `알림 보기`를 선택합니다. Mac 화면에서 `설정했어요 · 전송 테스트 시작`을 누른 후 개인정보 없는 화면에서 뒷면을 빠르게 두 번 탭해 캡처합니다. 단축어는 `iCloud Drive/KCC-inbox`에 저장합니다. Mac을 켜두고 동기화를 기다립니다. 새 파일이 수신되면 파일명을 표시하고 완료 버튼을 활성화합니다.
5. **시작하기**: `좋아요, 설정 마치기 → 내 파일 보러 가기`에서 완료를 저장하고 모든 파일 화면으로 이동합니다. Mac Safari의 파일 → Dock에 추가에서 `모아 AWS`로 저장합니다.

Mac에서 켜둔 도우미가 iCloud 파일을 읽고 AWS로 메타데이터를 보냅니다. iPhone에는 에이전트나 별도 앱을 설치하지 않습니다. 수신 검증은 새 파일이 Mac 스냅샷에 들어왔는지를 확인하며, 발신 기기가 iPhone이라는 하드웨어 인증은 제공하지 않습니다. 파일 원본은 KCC-inbox에 남고 작업 사본은 확실한 분류 계획일 때 자동 이동합니다. 애매한 파일은 사용자 결정을 기다리며, 이동은 되돌릴 수 있습니다.

진행 상황은 `library_onboardingprogress` 테이블에 사용자별로 저장합니다. iPhone 설정 확인, 테스트 시작 시각과 기존 파일 ID 목록, 완료 시각을 저장하며 다른 사용자에게 노출하지 않습니다. 같은 모아 계정으로 로그인하면 Mac과 iPhone에서 이어볼 수 있습니다. `나중에 하기`를 선택해도 연결 메뉴의 `Mac · iPhone 연결 가이드`에서 재개할 수 있습니다.

API: `GET/POST /api/v1/onboarding/`. POST action은 `confirm_iphone`, `start_test`, `complete`입니다. 완료는 Mac 온라인·iPhone 설정 사용자 확인·테스트 이후 새 파일 수신 조건을 서버에서 검사합니다. 기존 파일과 다른 사용자의 파일은 테스트 결과에 포함하지 않습니다.

동기화 문제 시 계정 일치, 저장 위치(iCloud Drive와 나의 iPhone 구분), Mac 절전, 도우미 실행, iCloud 다운로드 상태·저장 공간·네트워크를 확인하도록 안내합니다.

Apple 공식 설정 안내: https://support.apple.com/ko-kr/118443

## 화면 구성

한 화면에는 현재 할 일 하나만 표시합니다. Dock 추가 안내 다음 화면에서 iPhone → iCloud 폴더 → Mac·모아 흐름을 설명한 뒤, Mac 연결 / iPhone QR 및 폴더 확인 / 뒷면 탭 캡처 / 자동 수신 확인 / 완료 화면으로 이동합니다. Mac에서 진행할 때 iPhone 웹 로그인을 요구하지 않습니다. Mac 다운로드 / 실행 차단 해제 / 폴더 선택·연결, iPhone iCloud 폴더 / 단축어 추가·저장 폴더 / 이중 탭 설정을 각각 별도 화면에서 안내합니다. 문제 해결은 각 화면의 접힌 도움말에 있습니다.

Mac 연결 버튼은 설치된 연결 앱을 엽니다. 앱 창에서 연결을 승인하면 iCloud 폴더 준비와 AWS 연결이 이어지고, 웹앱에서 다음 단계가 표시됩니다. 단축어와 이중 탭 설정을 마친 뒤 전송 테스트 시작 버튼을 눌러 수신 기준을 저장합니다. 설치 중 생긴 파일은 테스트 기준에서 제외합니다.

## 다운로드와 앱 실행

Mac 연결 단계는 GitHub나 터미널 명령 대신 `/downloads/moa-mac-helper.zip`을 제공합니다. Apple Silicon과 Intel Mac을 모두 지원하며 macOS 14 이상이 필요합니다. 첫 다운로드 후 압축을 풀어 앱을 한 번 실행해야 하며 macOS 실행 확인은 사용자가 승인합니다. 배포본은 임시 서명된 개발용이며 Apple 공증은 아직 없습니다.

설치된 연결 앱은 `moa-helper://connect?ticket=...` 링크로 실행됩니다. 브라우저는 임의의 프로그램을 자동 설치·실행할 수 없으므로 최초 앱 열기와 macOS 승인은 생략할 수 없습니다. 설치 후에는 연결 버튼으로 앱 실행 → 앱 창에서 승인 → 로컬 연결까지 이어집니다. Safari 창은 추가로 열리지 않습니다. 5분짜리 연결 코드는 앱 메모리에서만 처리하며, 셸 인자·로그·설치 파일에 저장하지 않습니다.

앱은 `~/Applications/Moa Helper.app`에 등록하고 실행 소스와 Python은 `~/Library/Application Support/Moa/releases/<hash>`에 보관합니다. Safari Dock 웹앱은 교체하지 않습니다. 브라우저와 Dock 웹앱의 로그인이 분리될 수 있어, 설치 완료 후 기존 Dock 앱으로 돌아가도록 안내합니다.

## iPhone 단축어와 뒷면 탭

공유 단축어 이름은 `알림 보기`이며 스크린샷 촬영, 날짜 기반 이름 변경, iCloud Drive의 `KCC-inbox` 저장을 수행합니다. QR에는 계정 토큰 없이 공개 설치 안내 URL만 넣습니다. 단축어 추가는 사용자가 Apple 단축어 앱에서 승인합니다. 뒷면 탭 배정은 iPhone의 손쉬운 사용 설정이므로 공유 링크로 배포하거나 웹에서 자동 지정할 수 없습니다. 처음 실행할 때 파일 접근 권한 확인이 필요할 수 있습니다.

이 공유 단축어의 저장 액션은 공유자의 iCloud Drive `KCC-inbox` 폴더 참조를 담고 있습니다. 다른 Apple 계정의 iPhone에서 폴더 참조가 그대로 동작하는지는 실제 기기로 확인해야 합니다. 작동하지 않으면 해당 기기에서 저장 액션의 폴더를 자신의 `KCC-inbox`로 다시 지정해야 합니다.

## Mac 폴더 선택과 QWEN 지침

Mac 연결 앱의 승인 다음에 첫 폴더 설정 목록이 열립니다. `폴더 추가`로 서로 다른 위치의 폴더를 반복해서 담고, 각 폴더의 이름·경로를 확인합니다. `빼기`로 개별 폴더를 제외할 수 있습니다. 선택창에서 ⌘ 키로 여러 개를 함께 추가하는 것도 가능합니다. 모두 고른 뒤 `선택 완료 · 지침 만들기`를 누릅니다. 빈 목록에서는 완료할 수 없습니다. 최대 20개이며 상위·하위 폴더 중복 선택은 거절합니다. 선택을 취소하면 새 연결 작업을 시작하지 않습니다.

선택한 폴더의 바로 아래 파일·하위 폴더 이름을 최대 80개까지 참고해 Qwen3-1.7B가 한국어 정리 지침 README를 생성합니다. 저장명은 기존 분류 실행기와 동일한 `_project.md`입니다. 기존 `README.md`와 `_project.md`는 덮어쓰지 않으며, 링크는 따라가지 않습니다. 파일 본문은 읽거나 서버에 업로드하지 않습니다. 목적·보관할 자료·분류 기준·판단이 애매할 때 사용자에게 물을 기준을 작성합니다. 이름만으로 의미를 판단하기 어려우면 목적 확인이 필요한 것으로 남깁니다.

QWEN은 Mac 안의 별도 Python 환경(`Moa/qwen-runtime`)에서 실행합니다. 첫 사용에는 실행 패키지와 공식 `Qwen/Qwen3-1.7B` 모델 다운로드가 필요하며 앱 창에 준비·폴더별 작성 진행 상태를 표시합니다. 생성 실패를 규칙 기반 가짜 지침으로 대체하지 않습니다. 모든 폴더 지침이 준비된 뒤에만 `projects.json`을 교체하고 실행기를 새 설정으로 시작합니다. 이미 작성한 지침은 재시도 때 재사용합니다. 파일 이동은 지침 생성 작업에 포함하지 않습니다.

로컬 API `GET/POST /api/v1/local/folders/`는 로컬 설치, loopback 호스트, local-owner 세션이 필요하고 POST는 CSRF 검증을 적용합니다. POST 본문은 `{"folders":["/absolute/path"]}`이며 202를 반환합니다. GET으로 `preparing`, `loading_model`, `generating`, `completed`, `failed` 상태를 조회합니다. 동시에 둘 이상의 생성 작업을 시작할 수 없고, 앱이 중단되어도 작업 프로세스는 계속 진행합니다. 서버 연결 코드는 모델 다운로드 전에 교환해 5분 만료를 피합니다. 지침 생성이 완료되기 전에는 Mac 브리지와 분류 실행기를 시작하지 않습니다.

이 변경은 macOS Gatekeeper 공증 제한을 해제하지 않습니다. 일반 사용자용 배포에는 별도로 Developer ID 서명과 Apple 공증이 필요합니다.


## 연결 후 폴더 추가와 다운로드 감시

온보딩 완료 뒤에도 웹앱의 `폴더 → 폴더 추가` 또는 Mac 연결 앱의 `폴더 추가…` 메뉴로 새 폴더를 등록할 수 있습니다. `moa-helper://folders`는 로컬 선택창을 열며 연결 코드를 새로 발급하거나 AWS 연결을 끊지 않습니다. 한 번에 20개씩 추가하고 기존 폴더·지침·출처별 분류 규칙은 유지합니다. 새 지침이 모두 준비된 뒤 폴더 목록을 합치고 실행기를 새 목록으로 갱신합니다. 추가 작업 중 실패해도 기존 폴더의 감시는 계속됩니다.

로컬 폴더 API의 POST `mode: "add"`는 기존 목록에 추가하며, 생략 시 온보딩의 전체 선택(`replace`)입니다. 기존 폴더와 상위·하위 경로가 겹치는 추가는 거절합니다. 이미 등록된 같은 폴더는 중복 생성하지 않습니다.

Mac 실행기는 `~/Downloads`도 감시합니다. 완료된 지원 파일을 작업 사본으로 수집하고 원본은 보존합니다. 파일 크기가 안정된 후에만 수집하고, 처리한 크기·수정 시각을 기록해 재시작 시 중복 수집을 막습니다. 출처 규칙이나 충분한 분류 근거가 있어도 다운로드·스크린샷은 승인 전 이동하지 않습니다. 자동으로 분류 제안을 준비하고, 애매한 파일은 분류 대기 화면에서 폴더 선택을 요청합니다. PDF 텍스트는 Python에 포함되는 pypdf로 읽어 별도 pdftotext 설치가 필요 없습니다.


분류 대기 카드의 폴더 선택에는 `＋ 새 폴더 만들기…`가 있고 별도의 `새 폴더 만들기` 버튼도 제공합니다. `moa-helper://folders?create=1`로 Mac 앱을 열고, macOS 선택창의 `새로운 폴더`로 폴더를 만든 뒤 하나를 선택합니다. QWEN 지침 작성과 등록이 끝나면 웹의 폴더 목록이 갱신됩니다. 해당 파일에서 새 폴더를 고르고 `답변 보내기`로 분류 기준을 확정합니다. 파일 이동은 기존의 `계획 승인` 단계에서 수행합니다. 모델이 제안했던 후보 이외의 새 폴더도 답변 목록에서 선택할 수 있습니다.

## 처음 설치하는 사람을 위한 단계별 안내

Mac 앱이 차단되면 먼저 Finder에서 Moa Helper를 한 번 실행해 차단 안내를 확인합니다. 이어서  → 시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 보안 영역의 `그래도 열기` → 암호 또는 Touch ID 확인 → `열기` 순서로 진행합니다. 이 사이트에서 받은 앱인지 확인한 뒤 허용합니다. Helper의 준비 완료 안내를 확인한 다음 웹에서 연결 요청을 발급하므로 설치 중 연결 코드가 만료되는 일을 줄입니다. 실행이 허용된 앱은 실행 차단 단계를 건너뛸 수 있습니다.

iPhone 공유 단축어의 파일 저장 폴더는 해당 기기의 `iCloud Drive/KCC-inbox`를 직접 선택하고 `매번 저장 위치 묻기`를 끄도록 안내합니다. 이중 탭 동작 목록의 일반 `스크린샷`이 아니라 아래쪽 단축어 영역의 `알림 보기`를 지정합니다. 뒷면 탭을 사용할 수 없다면 단축어 앱에서 직접 실행해 테스트할 수 있습니다. 처음 요청되는 접근 권한을 확인하고 허용한 뒤, 권한 창이 캡처됐다면 다시 실행합니다.

QR로 여는 공개 `/#iphone-shortcut` 페이지와 Mac 온보딩은 `web/dist/setup-guides.js`의 안내를 함께 사용합니다. iPhone에서 로그인할 필요가 없고, 각 화면에서 이전 단계로 돌아가 설정을 다시 볼 수 있습니다. 온보딩 화면 전환은 온보딩 영역에만 적용되어 공개 안내를 숨기지 않습니다.

공식 메뉴 확인: [Mac 앱 실행 허용](https://support.apple.com/ko-kr/102445), [iPhone 뒷면 탭](https://support.apple.com/ko-kr/111772).

## 첫 일괄 정리와 기타 파일 제안

새 Helper의 연결 승인 화면에서 다운로드·스크린샷 일괄 정리 범위를 알립니다. 사용자가 폴더를 선택해 연결하면 `initial_cleanup: true`로 로컬 폴더 설정을 요청하고, 해당 Mac에 일괄 정리 동의를 저장합니다. 첫 폴더 설정의 기본값은 일괄 정리 활성화입니다. 기존 설치의 명시적 비활성화 설정은 보존합니다.

선택한 폴더의 지침 준비 뒤 Downloads와 macOS 스크린샷 저장 위치(기본 Desktop)의 기존 문서·이미지를 작업 공간으로 수집합니다. 스크린샷 위치에서는 이미지만 읽고 링크는 따라가지 않습니다. 원본은 유지하며 처리한 버전을 기록해 재시작 시 중복 수집을 피합니다. 지침·규칙에 맞는 파일부터 분류하고, 남은 파일은 같은 로컬 Qwen 실행 환경에서 폴더 지침과 내용 일부를 대조해 재분류합니다. 기존 폴더를 다시 제안하거나 새 폴더 이름과 목적을 제안할 수 있습니다.

모델은 JSON 제안만 만들며 폴더나 파일을 변경할 권한이 없습니다. `첫 일괄 정리` 및 온보딩 이후 `모든 파일`·`폴더`·`분류 대기` 화면에서 파일 목록·묶은 이유·폴더를 확인한 뒤 `이 분류로 정리` 또는 `이번에는 보류`를 선택합니다. 확인한 새 폴더에만 `_project.md`를 만들고 작업 사본을 옮깁니다. 실제 파일 해시와 현재 상태를 재검사하며, 이름 충돌·변경된 파일·다른 경로를 가리키는 링크가 있으면 제안 전체를 거절합니다. 중간 실행 오류는 처리한 이동을 되돌립니다.

많은 파일은 모델 입력과 제안을 묶음으로 처리합니다. 웹에는 한 번에 제안 20개와 크기가 제한된 최근 파일 메타데이터만 보내고 전체 건수는 별도로 유지합니다. 제안을 처리하면 다음 묶음이 이어집니다. 파일 본문·폴더 지침·로컬 생성 경로·파일 해시는 브리지 제안에 포함하지 않습니다. 모델 생성 실패를 임의 규칙 제안으로 대체하지 않으며 재시도를 제공합니다.

정리를 기다리지 않고 `iPhone 먼저 연결`로 진행할 수 있으며, 보류한 제안은 파일을 이동하지 않습니다. iPhone 전송 테스트는 새 Helper에서 iCloud 출처의 새 파일만 인정하므로 일괄 분류 중 들어온 다운로드가 테스트 성공으로 잡히지 않습니다.

다운로드·스크린샷은 기존 폴더로 확실하게 분류됐더라도 작업 사본을 자동 이동하지 않습니다. 기존 폴더 후보와 새 폴더 후보 모두 사용자가 확인한 뒤 실행합니다. `다운로드 · 스크린샷 다시 분석`은 보류·미확정 파일에 최신 지침을 다시 적용하며, 이미 승인해 이동한 파일과 그대로 두기로 결정한 파일은 유지합니다. 온보딩에서 분석 실패·미완료·제안 미확인 상태는 확인 완료로 처리할 수 없고, 명시적으로 나중에 확인하기를 선택할 수 있습니다.
