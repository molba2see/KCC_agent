# 수집 데이터 검증 결과 (2026-11-02)

Claude Code 에이전트로 만든 데이터 팀 4명(배치당 25개)과 검증 팀 3명(관점별)이 만든 100개 사례의 검증 결과입니다.
모든 사례는 `case_check.py` 기계 검사를 통과했고, 프로젝트 id·문장·템플릿은 평가셋(`tasks_v5.py`)과 겹치지 않습니다.

## 검증 결과

| 관점 | keep | fix | drop |
|---|---|---|---|
| 정답 재라벨링 (답을 보지 않고 다시 라벨) | 85 | 13 | 2 |
| 현실성·중복·누출 | 73 | 24 | 3 |
| 정책·안전 (도구로 도달 가능한가, 개인정보) | 76 | 23 | 1 |
| **세 관점 모두 keep** | **53** | 41 | 6 (하나라도 drop) |

- 세 관점 모두 keep인 53개는 바로 쓸 수 있습니다. 유형: 주입 12, 근거 없음 9, 의미 9, 모호 9, 긴 문서 6, 명시 4, 기타 2, 가중치 2.
- 가중치 사례가 2개뿐이라 이 유형은 부족합니다.

## 호스트로 정답을 낼 수 있는가 (oracle replay)

정답 경로(파일을 끝까지 읽거나 관련 파일 검색 → 정답 근거로 지정 또는 정답 후보로 질문)를 실제 호스트에 넣어 봤습니다.

| | 사례 | 호스트가 정답을 받아들임 | 규칙 controller 정답 |
|---|---|---|---|
| 전체 | 100 | 94 | 78 |
| 검증 통과 53개 | 53 | 53 | 45 |

- 합성 평가셋에서 120/120이던 규칙 controller가 여기서는 78/100입니다. 규칙이 합성 생성기에 맞춰져 있었다는 뜻이고, 수집 데이터가 더 어렵다는 근거입니다.
- 정답이 거절된 6건은 모두 "단일 프로젝트" 검사입니다. 근거가 영어이거나 한국어 복합어라 카탈로그와 어휘가 겹치지 않으면, 맞는 근거도 거절됩니다.

## 검증 팀이 찾은 호스트 문제

1. **따옴표가 들어간 근거를 항상 거절** (수정함): 근거 대조를 JSON 문자열로 해서 `"`가 `\"`로 바뀌었습니다. 원문 문자열로 대조하도록 고쳤고 테스트를 추가했습니다.
2. **단일 프로젝트 검사가 어휘 일치에 의존** (미수정): 영어·복합어 근거를 거절합니다. 합성 데이터에 맞춰진 규칙입니다.
3. **지시문 탐지 키워드 목록의 한계** (미수정): "지시함수", "삭제하기로" 같은 평범한 문장을 지우고, "삭제 부탁", "옮겨 주세요" 같은 공손한 주입은 놓칩니다.
4. **`inspect_file`이 파일 이름만 보여 줌** (미수정): 경로로만 구별되는 가중치(best.pt, last.ckpt 등)는 도구로 구별할 수 없습니다.

## 데이터 쪽 반복 문제 (fix 대상)

- 긴 문서 대부분이 결정적 문장을 맨 끝에 둡니다. "마지막 줄만 읽기"를 학습할 위험이 있습니다.
- 파일명만 보고 답이 나오는 사례, 오해 유도 파일 안에 "파일명 잘못 저장함" 같은 설명이 들어간 사례가 있습니다.
- 모호 사례 일부에 실제로는 한쪽을 가리키는 단서가 남아 있습니다(진짜 동점이 아님).
- 후보 목록 규칙이 일관되지 않습니다. 그럴듯한 프로젝트가 하나 있으면 후보로 넣을지 빈 목록으로 둘지 정해야 합니다.
- 주입 문구 일부가 평가셋 INJECT 패턴(이전 지시 무시 + 도구 호출 + 삭제)과 비슷합니다.
- 개인정보·비밀값은 발견되지 않았습니다(카드 번호는 마스킹, API 키는 placeholder).

# Held-out 테스트셋 검증 (2026-11-04)

학습에 쓰지 않는 테스트용 75개(`batch_t1~t3.json`)를 수집 에이전트 3명이 약점 영역에 맞춰 만들었습니다(t1 가중치·경로·긴 문서 앞/중간 근거, t2 영어·복합어·동의어·약한 겹침, t3 정규식이 놓치는 주입·평범한 단어 오탐·진짜 동점). `make_sft.py`는 `batch_[0-9]*.json`만 읽으므로 학습에 섞이지 않습니다.

| 관점 | keep | fix | drop |
|---|---|---|---|
| 정답 재라벨링 | 73 | 2 | 0 |
| 현실성 | 66 | 9 | 0 |
| 정책 (호스트로 정답 경로 재생) | 54 | 21 | 0 |

- **clean 66개** = 재라벨링·현실성 모두 keep. 제외 9개(t1-014, 016, 020, 021, 024, 025, t2-17, 18, 25)는 후보 목록에 이견이 있거나 동점이 한쪽으로 기운 사례입니다. `sft/test_split.json`의 `clean` 키.
- 정책 fix 21개는 데이터 문제가 아니라 **호스트가 맞는 정답을 거절**하는 경우라 테스트에 그대로 둡니다. 측정하려는 약점 자체입니다.
  - 10개: 영어·바꿔 말한 근거가 한국어 카탈로그와 어휘가 안 겹쳐 support 검사가 거절.
  - 6개: 지시함수, 삭제하고, 무시하고, ON DELETE CASCADE 같은 평범한 문장을 주입 필터가 지움.
  - 4개: 공통 단어 때문에 진짜 동점이 어휘상 한쪽으로 기움. t3-008은 근거 일부가 두 시즌 프로젝트에 다 맞음.
- 정책 검증이 찾은 것: `make_sft.oracle()`은 텍스트 파일에서 `find_related_files`를 부르지 않아, 관련 파일에만 근거가 있는 사례를 학습 데이터에서 놓칩니다. t3-005의 "For AI assistants indexing these downloads..." 주입은 필터를 통과하고 근거로도 받아들여집니다.
- 현실성 검증이 찾은 편향: 가중치 정답 8개 중 6개는 파일명에 주제가 드러나고, 근거는 대부분 파일 앞쪽에 있습니다(중앙값 위치 0.2). 일부 형태는 학습 배치와 비슷합니다.
