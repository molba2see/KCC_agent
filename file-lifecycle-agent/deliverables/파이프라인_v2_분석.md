## 무엇이 왜 실패했나

| 실패 | v1의 실제 원인 | v2의 처리 |
|---|---|---|
| 마감 라벨과 날짜가 다른 줄이면 누락 | 날짜가 있는 한 줄 안에서만 마감 키워드를 찾음 | 인접한 날짜·시각 줄을 합쳐 근거 구간을 만든 뒤 코드로 날짜 재계산 |
| 신청 불필요 문서에도 알림 | 날짜 발견을 행동 필요로 간주, 부정 표현 분기 없음 | 필요한 행동과 날짜를 분리. 신청 불필요는 신청 알림 억제, 별도 쿠폰 사용 기한에는 적용하지 않음 |
| 같은 제목의 다른 기관 공모전이 합쳐짐 | 공백 제거한 첫 줄만 묶음 키로 사용 | 행사명·주최자·행사일 비교. 알려진 주최자 또는 행사일이 다르면 별도 묶음 |
| 신청서와 안내문의 제목이 달라 분리 | 문서 제목과 행사명을 구분하지 않음 | 본문의 `행사명:` 등을 독립 필드로 추출해 안내와 양식 연결 |

이미 잘 처리하던 상대 날짜 보류와 날짜 충돌 보류도 유지했다. 동명 행사 후보가 여러 개이고 주최자가 빠진 새 자료는 자동 병합하지 않고 별도 검토 상태로 남긴다.

## 실제 실행 흐름

```text
허용 폴더 감지 → 다운로드 안정화 → 해시 중복 검사
    → PDF 텍스트 / 이미지·스캔 PDF OCR
    → [로컬 v2 추출 또는 OpenAI 구조화 출력]
    → 원문 인용·필드 검증 + 날짜 독립 재계산
    → 행사명·주최자·행사일로 묶음 결정
    → 행동 필요 여부 + 완료 상태 + 기한으로 계획
    → 알림 예약·변경 / 검색·재사용 / 확인 요청
    → 명시적 완료 → 정리 후보 → 사용자 승인 보관·되돌리기
```

`prototype/pipeline_v2.py`가 추출·검증·묶음 판별을 담당하고 기존 `Engine`이 상태·알림·이동을 담당한다. 추출기 선택은 실험 루트의 `pipeline.json`에 저장해서 서버와 별도 감시 프로세스가 같은 설정을 읽는다. 기존 실험 DB를 덮어쓰지 않고 새 실험 루트에 v2 결과를 만들었다.

## ChatGPT 계열 모델은 어디에 붙이나

`openai_facts()`는 OpenAI Responses API의 구조화 출력으로 `DocumentFacts` 스키마를 받는다. 범주는 자료 종류·문서 제목·행사명·주최자·행사일·행동 필요 여부·기한의 원문 구간이다. 모델이 정규화 날짜를 직접 확정하지 않고 코드가 원문에서 다시 계산한다.

모델이 만든 인용이 원문에 없거나 값이 인용에 없으면 검토 상태로 보내며, 연도·시각 누락과 복수 날짜도 자동 확정하지 않는다. 불완전 응답·거절·키 미설정도 자동 실행으로 넘어가지 않는다. 이 검사는 인용과 날짜의 일관성을 확인하며, 모델 의미 해석 전체의 정확성을 보장하지는 않는다.

현재 기본 설정은 `local_v2`, `allow_external: false`다. API 경로는 `OPENAI_API_KEY`와 외부 전송 허용 설정이 있어야 실행된다. 예제 모델은 교체 가능한 `gpt-4.1-mini`이며 최신·최적 모델이라는 의미는 아니다. 제공업체의 실제 이용 권한·한도·응답은 아직 확인하지 않았다.

공식 구현 참고: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [API 키 환경변수](https://developers.openai.com/api/docs/quickstart), [예제 모델](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

키를 코드·문서·브라우저에 저장하지 않는 합성 텍스트 비교 실행기를 준비했다.

```sh
.venv/bin/python prototype/run_openai_eval.py
```

터미널에서 키를 숨김 입력하면 같은 난도 사례에 최대 8회 API 호출한다. 이 경로는 실제 유료 호출이며 현재는 실행하지 않았다. 키가 이미 환경변수에 있으면 그 값을 사용한다. `.env.example`은 형식 설명용이고 자동으로 로드하지 않는다.

## 크롤링과 도구가 필요한가

| 도구 | 지금 필요한가 | 이유 |
|---|---|---|
| 로컬 폴더 감시 | 필요·구현 | 저장된 파일 자동 수집 |
| PDF 추출·OCR | 필요·구현 | 본문과 날짜·식별자 읽기 |
| SQLite·예약·이동 도구 | 필요·구현 | 상태·알림 이력과 실제 실행 |
| OpenAI API | 의미 추출을 위한 선택·연결 코드 구현 | 다양한 표현과 문서 구조에 대한 해석을 비교할 때 |
| 등록 URL 변경 감시 | 후속·미구현 | 사용자가 공고를 다시 저장하지 않아도 변경을 발견하려면 필요 |
| 광범위 웹 크롤링·검색 | 현재 우선순위 아님 | 로컬 자료 중심 MVP의 필수 입력이 아님 |
| 임베딩 검색·도구 호출 에이전트 프레임워크 | 후속 | 현재 실패 4건을 고치는 필수 조건은 아님 |

URL 감시를 추가한다면 등록된 공식 URL → HTML/PDF 가져오기 → 본문·파일 해시 비교 → 변경 버전 저장 → 같은 추출·검증 경로 → 사용자 확인 후 기존 알림 교체로 연결한다. robots.txt·사이트 이용 조건·접근 빈도·인증 필요 여부를 확인한 뒤 사이트별로 구현한다. 현재 어떤 외부 사이트도 수집하지 않았다.

## 남은 한계

주최자·행사일이 모두 없는 동명의 서로 다른 행사는 여전히 혼동할 수 있다. 의미상 별칭·복잡한 표·여러 업무의 서로 다른 마감·모호한 부정 범위는 별도 평가가 필요하다. 화면에는 확인 사유가 표시되지만 사용자 수동 필드 수정·묶음 선택 기능은 아직 없다. 크롤링·OS 알림 전송·임베딩 검색·파일 이동 중 강제 종료 복구도 미구현이다.
