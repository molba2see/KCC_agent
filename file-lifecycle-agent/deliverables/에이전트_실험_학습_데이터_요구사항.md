# 에이전트 실험·학습·데이터 요구사항

작성: 2026-11-02. 아래 수량은 착수용 제안이며 검증된 최소 학습량이 아니다. 아직 모델 추론/학습을 실행하지 않았다.

## 현재 판단

학습 없이 고정·규칙·모델 controller를 먼저 비교한다. 모델 호출이 필요한 상황과 규칙이 충분한 상황을 확인하고, 검색/추출 오류와 행동 선택 오류를 구분한다. 지금의 30개 반복 패턴 실험은 컨트롤러 배선 확인이며 모델 학습 자료나 독립 평가셋이 아니다.

## 선행 구현

현재 ToolHost는 빈 arguments만 받고 명시적 project_id에만 귀속한다. 다음으로 search_projects(query, candidate_limit), find_related_files(query, allowed_project_ids), read_content(asset_id, locator), check_references(asset_ids), ask_user(candidate_ids, question)를 타입 스키마로 확장한다. asset_id는 호스트의 허용 집합에서만 선택할 수 있고 모델이 준 경로를 직접 실행하지 않는다. 관찰에 출처·locator·잘림 여부를 기록한다. 모델별 tool template/parser를 고정하고, 잘못된 호출과 없는 ID를 거절한다. 실제 함수 호출 템플릿과 현재 단순 JSON action 어댑터를 동일 조건이라고 부르지 않는다.

## 실행할 실험

|순서|질문·조건|필요 데이터|지표|학습|
|---|---|---|---|---|
|A0|모델이 유효한 도구·인자를 선택하는가?|합성 20개 smoke case, invalid ID·반복·잘못된 스키마 포함|유효 호출·잘못된 성공 종료·예산 초과·인자 오류|없음|

A2 oracle context는 파서/검색 영향 분리용 진단 조건으로 raw-only 결과와 분리한다. oracle에 정답 행동 자체는 주지 않는다. top-k보다 정답 파일 수가 많은 문항은 정답 수별 층화와 이론 상한을 함께 보고한다.

## 데이터를 어떻게 만들 것인가

에피소드마다 goal, 허용된 초기 파일/프로젝트 상태, 금지 행동, 정답 관계, 허용되는 최종 계획 집합, 필요한 근거, 질문 필요 여부를 evaluator 전용으로 작성한다. 하나의 유일한 도구 호출 순서를 강요하지 않고 최종 목표·제약과 예산을 채점한다. 파일 본문에 명시적 ID가 있는 쉬운 사례와, 여러 도구 결과를 결합해야 하는 사례를 구분한다.

실제 자료를 쓸 때는 개인 문서 전체 대신 권리와 개인정보 처리가 확인된 복사본을 사용한다. 코드·설정·가중치 묶음은 경로/설정 참조/필수 산출물 관계 라벨이 필요하다. 최고 성능 체크포인트 판단에는 별도 평가 로그가 필요하며 파일명만으로 라벨링하지 않는다.

추가 라벨은 프로젝트 귀속, referenced_by/version_candidate/duplicate, 활성/완료/재개 사건, 공유 참조, keep/archive/defer 허용 집합, 필요한 사용자 확인이다. 일부 표본은 2인이 독립 검수하고 불일치를 조정한다. 파일·프로젝트·버전 묶음이 개발/평가를 넘나들지 않게 분할한다.

도구 trajectory의 학습 단위는 observation → tool name/arguments → tool result → 다음 행동/종료다. 짧은 근거 요약과 출처만 남기며 비공개 사고 과정은 필요하지 않다. 모델이 자동 생성한 성공 주장이나 validator 통과만으로 정답 라벨을 만들지 않는다. 실패/거절/질문 사례도 검수 후 포함한다.

HippoCamp는 우선 검색·근거 평가에 사용한다. 프로젝트 귀속·최적 목적지·보존 시점의 정답으로 자동 변환하지 않는다. 공개 평가셋을 학습에 넣지 않고, 이용조건과 학습 허용 범위를 확인한 별도 자료로 학습한다. 현재 받은 175개 파일과 12개 평가 문항은 제한된 raw-only 기준선이며 전체 일반화 성능이 아니다.

## 모델과 자원

- 첫 controller 기준선: 기존 인계에 있는 Qwen2.5-3B-Instruct. 현재 보유·가용성은 서버 재확인 전 미검증. 작은 모델의 비용/문법/행동 오류 기준선으로 쓴다.
- 비교 후보: Qwen3-8B. 공식 function-calling 템플릿을 고정해 비교한다. 로드 가능 여부는 실제 GPU 사용량·문맥 길이·정밀도·런타임 오버헤드를 측정한 뒤 판단한다.
- 검색: BM25부터 시작. 기존 BGE reranker가 실제로 있으면 동일 후보 집합 재정렬만 비교한다. reranker는 controller도, 문서를 인덱싱하는 임베딩 모델도 아니다.
- 사진: 필요할 때 Qwen2.5-VL-3B-Instruct 같은 기성 시각언어 모델을 별도 비교한다. 처음부터 시각 모델을 학습하지 않는다.
- GPU가 필요한 곳: 모델 controller/VLM 추론과 조건부 LoRA. 파일 수집·BM25·스키마 검증·저널·복구에는 GPU가 필수는 아니다. 기존 공유 작업과 잠금을 확인하고 별도 실험 디렉터리/환경을 사용한다.

## 언제 학습하는가

충분한 근거를 제공해도 도구 선택·인자·종료 판단 오류가 반복되고, 스키마·템플릿·프롬프트·예산 설정을 고친 뒤에도 고정 평가셋에서 개선 여지가 있을 때 LoRA를 검토한다. 근거가 검색되지 않는 경우는 검색 개선이 먼저고, 글자 없는 사진은 OCR 학습이 해결책이 아니며, 위험한 이동 허용은 모델 학습 대신 실행기 제약으로 막는다.

학습 전후는 동일 기반 모델·도구·컨텍스트·출력 예산으로 비교하고 무학습 controller를 반드시 유지한다. 재학습 데이터가 평가 프로젝트를 포함하지 않는지 검사한다. 한 번의 상승만으로 채택하지 않고 케이스별 회귀와 비용을 함께 확인한다. 강화학습과 멀티 에이전트는 첫 필수 범위가 아니다.

## 서버 접속 상태

Backend.AI 기존 관리 탭은 로그인 화면이며 자동으로 사용할 로그인 정보가 표시되지 않았다. 기존 SSH 포트 연결은 reset 상태다. 재로그인 완료 전 원격 모델 파일·현재 GPU를 확인했다고 주장하지 않는다. 사용자에게 계정 로그인 UI를 통한 인증 완료를 요청한 상태이며 비밀번호·키 내용은 문서나 채팅에 남기지 않는다.
