# 발표 기능·설정 구현 계획

## 동작 정책

- 첫 일괄 정리 및 앱 시작 전에 이미 있던 다운로드·Mac 캡처는 확인 후 정리한다.
- 실행 중 새로 들어오는 다운로드·Mac 캡처·iPhone 파일은 출처별 설정에 따른다. 기본은 근거가 충분하면 자동 정리하고, 모호하면 사용자에게 묻는다.
- 설치파일은 최초 발견 이후 기본 3일 뒤 휴지통으로 이동한다. 설정에서 비활성화·기간 변경이 가능하다. 영구 삭제는 수행하지 않는다.
- 휘발성 자료는 이름에 명확한 임시·공지 단서가 있을 때 기본 7일 기한을 제안하며, 기본은 승인 대기다. 설정에서 끄기·자동 예약도 선택한다. 일반 파일은 개별 삭제 예약도 지원한다.
- 웹 설정은 선택한 Mac에 명령으로 전달하고, 적용된 설정과 버전을 다시 확인한다. 오프라인·구버전·다른 사용자의 Mac에는 적용하지 않는다.

## 구현 순서

1. 영속 설정과 출처별 신규 파일 처리 정책을 구현한다. 기존 파일과 신규 파일을 감지 시점·버전으로 구분한다.
2. 예약·보류·승인·취소·변경·복구가 가능한 만료 실행기를 구현한다. 파일 교체, 중복 이름, 링크, 재시작과 이동 실패를 방어한다.
3. 웹 설정 및 삭제 관리에 실제 상태·예정 시각·행동 버튼을 연결한다.
4. 모델 출력 오류를 묶음별로 격리하고, 제안할 수 없는 파일은 개별 분류 대기에 남긴다.
5. 임시 파일의 만료·복구 및 브리지 명령·PC/모바일 UI를 검증하고 실제 모델로 재확인한다.
6. GitHub 및 https://3.38.192.19/ 에 배포하고 설치된 Mac 연결 앱도 갱신한다.

개별 파일 본문이나 비밀키를 검증 결과·작업 문서에 기록하지 않는다. 검증 중 사용자의 파일을 임의로 삭제하거나 분류 제안을 승인하지 않는다.

## 구현·검증 기록

- 출처별 영속 설정, 설정 버전 검증, 신규 파일 자동 정리와 기존 파일 확인 분리를 구현했다.
- 설치파일 및 휘발성 작업 파일의 예약·승인·변경·취소·복구를 구현했다. 동명 파일 교체 시 기한을 재설정하고, 휴지통 이동은 덮어쓰기 없이 수행한다. 참조·유지 중인 자료는 보호한다.
- 잘못된 모델 제안은 개별 분류로 넘기고 나머지 분석은 계속한다. 실제 Qwen 시험에서 시험 자료 2개를 처리해 제안 2개를 생성했다.
- 분석 중 생존 신호, 명령 전달 보류, sslip.io에서 운영 IP로의 기존 연결 이전을 구현했다.
- Python 테스트 152개와 브라우저 회귀 테스트 13개 파일이 통과했다. PC·모바일 설정 저장, 예약·변경·취소·복구 경로를 확인했다.
- GitHub main 및 https://3.38.192.19/ 배포를 완료했다. 웹/API 검사, Mac 앱 빌드와 Pages 배포가 GitHub Actions에서 모두 성공했다.
- 설치된 연결 앱을 소스 버전 `3f7f87ba66d8`로 갱신했다. 기존 계정·연결 토큰·선택 폴더는 유지했다. 브라우저에서 실제 설정 저장 → 브리지 전달 → 영속 설정 버전 1 → 적용 완료 표시와 새로고침 후 유지까지 검증했다.
- 설치된 앱의 기존 파일 16개 재분석이 `review`로 완료됐다. 정리 제안 13개와 개별 확인으로 남긴 파일 2개를 확인했다. 제안에는 복수 파일이 포함될 수 있다. 승인 없이 이동한 기존 파일은 0개다.
- 실제 예약 목록은 설치파일 2개의 예약과 휘발성 자료 1개의 승인 대기 제안이다. 사용자 파일의 실제 만료 이동·복구를 시험하지 않았으며, 해당 작업은 임시 파일로 검증했다.
- 기존 연결 주소를 운영 IP로 갱신했고, 운영 서버가 최신 Mac의 생존 신호와 설정·예약 기능을 수신함을 확인했다. 연결 초기화나 재연결은 필요하지 않았다.
