## 실제 설치에서 확인한 문제

현재 로컬 API는 정상 응답하고 `preview`, `cleanup_scan` 기능을 노출한다. 그러나 일괄 정리 상태는 `failed`, 모델 처리 수는 0이다. `workspace/cleanup-model.log`에서 `Folder name must reuse the observed topic`에 이어 `Model did not produce a valid folder name`으로 종료된 것을 확인했다. 폴더 이름 검증을 유지하면서 잘못된 제안만 보류하고 나머지를 계속 처리하도록 오류 격리가 필요하다.

설치파일 만료 코드를 임시 폴더에서 시험해 다음 두 문제도 재현했다.

- 같은 이름으로 파일을 교체해도 최초 감지 시간이 유지돼 새 파일에 오래된 만료 기한을 적용한다.
- 휴지통에 원래 이름과 시각을 붙인 대체 이름이 둘 다 있으면 기존 휴지통 항목을 덮어쓸 수 있다.

삭제 기능을 서비스에 연결하기 전에 파일 버전 확인과 충돌 없는 휴지통 이동을 보완해야 한다.

## 확인 근거와 검증 범위

- `docs/index.html`: 같은 페이지의 후속 다운로드 자동 정리, 설치파일 3일 후 휴지통 이동·복구, 삭제 예정 UI를 발표 내용으로 제시한다.
- `web/local/run.py`: Downloads, 스크린샷, iCloud 감시 인자는 있으나 `--expire-installers-days`는 없다. 실제 실행 프로세스에서도 동일하게 확인했다.
- `file-lifecycle-agent/prototype/demo_v5.py`: 다운로드·Mac 스크린샷 승인 대기 정책과 옵션이 켜졌을 때만 시작하는 만료 실행기가 있다.
- `file-lifecycle-agent/prototype/expiry.py`: 지원 대상, 최초 감지 시각 기반 기한, 휴지통 이동·복구를 구현한다.
- `web/dist/agent.js`: 예정 목록은 `archive` 계획을 표시한다.
- 다운로드 감시 테스트 7개, 기존 파일·스크린샷 수집 테스트 3개와 만료 코드의 기본 이동·복구 검증이 통과했다.
- 설치된 OCR 실행 파일에 테스트 이미지를 전달해 정상 종료와 인식 영역 14개를 확인했다.
- 실제 새 스크린샷 촬영·브라우저 다운로드·iPhone 공유 단축어를 통해 전체 흐름을 재현한 검증은 이번 점검에 포함하지 않았다. 삭제 시험은 임시 폴더에서만 실행했다.

우선순위는 일괄 분석 실패 처리 보완 → 신규 파일의 자동 정리 정책 확정 → 설치파일 만료 안전성 보완 및 실행기·웹 연결 → 휘발성 자료의 기한 제안·승인·취소 구현 순서다.
